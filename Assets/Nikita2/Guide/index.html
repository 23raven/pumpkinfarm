ФЕРМА

Вырастить тыкву

  1. Выбери Hoe и вспаши клетку.
  2. Выбери семена и посади их.
  3. Поливай растение каждый игровой день.
  4. Собери зрелую тыкву. Забытая без воды тыква завянет — убери её мотыгой.
ПОЧТА И ЗАКАЗЫ

Получить оплату

  1. Загорелся значок на почтовом ящике — подойди и нажми SPACE.
  2. Нажми Read. Только после прочтения заказ появится на HUD.
  3. Найди здание с индикатором активного заказа и принеси нужные предметы.
  4. Выполни заказ, получи деньги и дождись новых писем в следующие игровые дни.
МАГАЗИН И СКЛАД

Покупать и хранить

  1. Подойди к магазину или хранилищу и нажми SPACE.
  2. В магазине покупай и продавай товары. Открытое окно блокирует движение.
  3. Склад используй для предметов, которые не нужны прямо сейчас.
  4. Закрывай окно его кнопкой Close. Письмо закрывается кнопкой Read.
Важно: активный слот определяет, что произойдёт при взаимодействии. Перед нажатием SPACE проверь подсветку клетки и выбранный предмет.

Как идёт связь: игрок вызывает IInteractable; системы получают нужные сервисы через GameServices; события идут через GameEvents; UI показывает результат. GameplayInputGate временно блокирует управление, когда открыто окно.

Главные связующие скрипты

GameServices находит сервисы. GameEvents рассылает сообщения. IInteractable связывает игрока с объектами мира. GameplayInputGate блокирует управление, пока открыта панель.

Где лежат заготовки

Assets/Nikita2/Prefabs — префабы объектов из твоего текущего рабочего уровня. Они помогают понять состав объектов и быстро восстановить похожую тестовую сцену. Это не финальная библиотека универсальных префабов; позже нужные повторяемые части можно будет привести к общему стандарту.

!
Чтобы не получить дубли

Перед добавлением префаба открой его через Open и посмотри Hierarchy внутри. Если Buildings.prefab уже содержит магазин или почту, не добавляй эти же здания повторно отдельными вариантами.

ДАННЫЕ ВМЕСТО НОВОГО КОДА

Как добавлять контент

Большинство новых вариантов игры должно добавляться через ассеты и prefab-настройки. Пиши новый скрипт только если появилось новое поведение, а не просто новый предмет.

NO CODE FIRST
◉
НОВЫЙ ПРЕДМЕТ

Сделать предмет

  1. Создай ItemDefinition в Data/Items.
  2. Заполни уникальный Item Id, English Display Name и Max Stack Size.
  3. Создай pickup prefab со своим SpriteRenderer/Collider/PickupItem/WorldItemPulse.
  4. Назначь этот prefab в поле WorldPrefab предмета.
Обычно не нужен новый класс.
♧
НОВАЯ КУЛЬТУРА

Добавить растение

  1. Создай ItemDefinition семян и урожая.
  2. Создай CropDefinition, назначь Seed Item, Harvest Item, спрайты по порядку и Withered Sprite.
  3. Добавь ассет в FarmTilemapController → Available Crops.
  4. Проверь Tilemap, watering overlay и каждый этап роста.
FarmCropSystem остаётся общим для культур.
＄
НОВЫЙ МАГАЗИН

Добавить товар

  1. Создай ShopProductDefinition, назначь цену и доступность покупки/продажи.
  2. Добавь ассет в ShopCatalog → Products.
  3. Убедись, что ShopStation на здании ссылается на нужный Catalog.
ShopPanelController сам создаст строку товара.
✉
НОВЫЙ БИЗНЕС

Добавить источник заказов

  1. Создай DemandSourceDefinition с уникальным Source Id и вариантами заказов.
  2. Добавь ассет в DailyOrderService → Sources.
  3. На здании добавь SalesSourceStation, назначь Source и child ActiveOrderIndicator.
  4. Проверь: пришло письмо → прочитал → индикатор показался → заказ можно выполнить.
У каждого бизнеса свой Source Id.
▣
НОВОЕ ХРАНИЛИЩЕ

Добавить склад

  1. Создай prefab здания с Collider2D, StorageContainer и StorageStation.
  2. Настрой Display Name и Slot Count.
  3. Поставь экземпляр в сцену.
Новая покупка и отдельный скрипт не нужны.
✦
КОГДА НУЖЕН КОД

Новое поведение

Если объект делает то же самое, но с другими данными — сделай новый ассет. Если действие действительно новое, проверь существующие интерфейсы и события, затем добавь небольшой компонент с одной ответственностью.

Не создавай новый Manager только ради одной ссылки.
КОГДА ЧТО-ТО НЕ РАБОТАЕТ

Карта быстрой диагностики

Проверь наиболее частые связи перед тем, как переписывать код.

DEBUG
Space ничего не делает

Проверь: у объекта в мире есть Collider2D; активен PlayerInteractor; объект реализует IInteractable; расстояние до InteractionPoint внутри радиуса; на сцене один активный Player. Для Tilemap проверь TilemapCollider2D и Tile Collider Type.

GameServices не находит сервис

На сцене должен быть ровно один активный GameServices. Сам сервис должен быть активен и зарегистрироваться. Для сервисов обычно не нужно заполнять поля на каждом объекте — они берутся через GameServices.Instance.TryGet<T>().

HUD не обновился

Проверь наличие HUDDisplayBridge, HUDPresenter и HUDTextBinding с правильным ключом. Для карточек инвентаря отдельно нужны InventoryHUDController, InventoryLayoutChangedEvent, назначенный Card Prefab и Card Root.

Drag & Drop не работает

Нужны Canvas с GraphicRaycaster, активный EventSystem, Raycast Target на карточке и корректные ссылки в Card Prefab. Дочерние иконки/тексты иногда стоит исключить из Raycast, чтобы события попадали в корень карточки. Для хранения/инвентаря проверь, что ScrollRect не перекрывает область перетаскивания.

Не отображается затемнение политой тыквы

Под Grid должен быть пустой дочерний Tilemap с точным именем WaterOverlayTilemap. Рисовать в нём не нужно. Его Tilemap Renderer должен использовать совместимый Sprite-материал (не пользовательский шейдер смешивания текстур, который игнорирует цвет/альфу). Слой сортировки обычно на 1 выше основного FarmTilemap.

MailIndicator не пропадает

В MailboxStation → Unread Indicator назначай дочерний объект MailIndicator из Prefab Mode или из экземпляра в сцене, а не сам Prefab Asset из Project. Индикатор должен реагировать на события MailReceived/MailRead. Убедись, что кнопка Read действительно вызывает MailboxService.MarkRead().

Покупка улучшения прошла, но слотов не прибавилось

У ShopProductDefinition проверь Product Type, уникальный Product Id и Capacity Bonus > 0. Для рюкзака — BackpackUpgrade; для тележки — CartUpgrade. ShopService должен быть зарегистрирован, а CartService должен иметь префаб тележки.

Поле было исправлено на сцене, но потерялось в Prefab

Если настройка сделана на экземпляре prefab в Hierarchy, используй Overrides → Apply, когда нужно сохранить её как настройку всех будущих экземпляров. Для ссылки на дочерний объект (например, MailIndicator) редактируй сам prefab в Prefab Mode.

✓
Правило команды
